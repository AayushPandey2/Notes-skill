# Visuals and media

Load only when a figure, diagram, table, or video frame would make a requested explanation clearer. Start with the learning difficulty the visual should solve. Prefer a direct Markdown table for comparisons or traces and native Mermaid for simple causal flows or state changes. Use a real figure when geometry, appearance, axes, or observed data matter. Do not create standalone HTML or JavaScript viewers, synthetic SVG figures, or a new rendering program.

For an external image, find its original source and file-specific reuse rights. Check that the content, labels, axes, units, and level suit the lesson. Download to the authorized vault's `assets/scriptorium/<collection-slug>/` only with available native tools, inspect the saved image with an available image viewer, and embed the local file with source and license attribution. Source-only requests may use only images supplied by or within the permitted source unless the user authorizes external material. Do not infer rights from a search thumbnail or invent a URL.

Teach with **Explain → Show → Decode → Connect**: introduce what to inspect, show the image, explain its labels and relationships, then tie its lesson to the next claim or equation. If rights, access, download, or inspection cannot be established, omit the image or mark the need unmet; do not claim the asset was verified. Live Obsidian rendering, byte validation, content hashes, and remote availability require a tool that actually performs those checks.

For video, distinguish transcript access from inspected frames. Attach timestamps only to source segments that can be located. If frames are unavailable, a transcript can still support text notes; report the narrower access state.

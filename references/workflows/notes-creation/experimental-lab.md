# Companion experimental lab

For each newly generated content note, create or update exactly one sibling `<note stem> - Experimental Lab.md`. Exclude MOCs, labs, assets, and internal workflow documents; do not create labs retroactively across a vault. Link parent and lab reciprocally. Use the active metadata profile without adding keys, and preserve the parent's notation and source limits.

Choose **one** template from the practical learning objective, not a keyword. Use [Machine Learning](../../templates/labs/machine-learning.md) for data, fitting, validation, and inference; [Deep Learning](../../templates/labs/deep-learning.md) for tensors, architectures, gradients, and training dynamics; [Mathematics](../../templates/labs/mathematics.md) for proof, derivation, and counterexample; [Physics](../../templates/labs/physics.md) for physical models, measurements, and uncertainty; [Chemistry](../../templates/labs/chemistry.md) for chemical systems, reactions, and evidence; or [General](../../templates/labs/general.md) for another investigation. For an interdisciplinary objective, select the primary structure and incorporate relevant material inside it. Examples: classical classifier comparison → ML; neural-network optimization → DL; matrix-identity proof → mathematics; circuit-response measurement → physics; acid–base investigation → chemistry; usability comparison → general.

Use the selected template's headings and order, including its track headings. Keep a genuinely inapplicable subsection with a specific reason rather than inventing evidence or quietly removing it. Begin with subject/topic, level, prerequisites, practical objective, investigation question, outcomes, materials or tools, expected deliverable, and constraints. Include languages and libraries for computational work; apparatus or substances for physical work. Adapt the shared progression: **Understand → Model or derive → Construct or investigate → Observe → Explain → Compare → Diagnose → Verify → Apply**.

Teach mathematical or procedural steps from intuition to technical detail. Map important operations to their symbols, inputs, types/shapes or units, and outputs; trace a small example. Give each displayed formula its collapsed walkthrough under [math_gates.md](../../../shared/math_gates.md). State hypotheses, controls, procedure, observations, interpretation, and limits where an investigation calls for them. Distinguish source facts, derivations, expected behavior, illustrative calculations, actual observations, and verified execution. Never invent measurements, code runs, results, or library APIs. Keep educational code inside Markdown fences and label unexecuted code `Status: static review (not executed)`.

Plan visuals section by section using [representations.md](representations.md). Native Mermaid explains flow; inspected local raster assets explain geometry, appearance, apparatus, structures, architecture, or graphs; tables show exact values. A general reference figure is not experimental evidence. Review the saved note and assets with [verification-checklist.md](../validation/verification-checklist.md).

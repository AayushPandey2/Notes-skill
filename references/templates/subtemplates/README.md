# Knowledge-Type Subtemplates

Subtemplates adapt **how** a subject is taught inside any selected master (`M1`–`M7`). Multiple subtemplates combine cleanly for hybrid topics (e.g., `mathematical` + `computational` for backpropagation).

- [mathematical.md](mathematical.md) — Formal notation, hypotheses, derivations, proofs, counterexamples, and boundary regimes.
- [computational.md](computational.md) — Algorithms, invariants, complexity, code-to-math mapping, testing, and debugging.
- [scientific.md](scientific.md) — Physical intuition, models, units, experimental conditions, uncertainty, and applicability regimes.
- [conceptual.md](conceptual.md) — Definitions, distinctions, arguments, near misses, and conceptual transfer.
- [historical.md](historical.md) — Chronology, primary-source context, causal evidence, and competing interpretations.
- [empirical.md](empirical.md) — Datasets, methodology, statistical metrics, ablations, replicability, and limitations.

## Comprehensive composition profile

The [composition contract](../../workflows/notes-creation/composition-contract.md) defines full-topic M1 collections: one MOC, five comprehensive chapters, shared S01?S18 capabilities in the existing instructional registry, independent depth dimensions, and authored publication with exactly five YAML keys. Its profile-specific rules take precedence over legacy collection metadata and file layout above. Existing single-note and M2?M7 contracts remain supported.

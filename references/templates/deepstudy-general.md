# DeepStudy-General

**Use for:** conceptual theory, systems architecture, historical development, non-code reasoning, and explanations where implementation is secondary.

**Research:** authoritative textbooks, standards, technical documentation, and reliable original material. Use foundational papers when the original result or history matters; do not require papers for every topic.

## What am I trying to understand?

State the question, why it matters, scope, and learning outcome. Identify the real-world situation where this understanding is useful.

## Overview

Give a plain-language explanation, prerequisite terms in dependency order, a small readiness check, and the concept's place in a broader system or field. Define the governing principle and its domain of validity.

## How it works

Break the mechanism, causal process, argument, or historical sequence into justified steps. Use one named running example or case throughout. Include a focused Mermaid architecture/sequence diagram for a system with three or more interacting components; use a timeline or evidence sequence when that better matches the topic.

## Intuition / Mental Model

Map an analogy to the real concept, explain where the analogy breaks, and distinguish the concept from its nearest confusable alternative. Predict what changes when a relevant condition changes.

## Details

Explain first principles, assumptions, terminology, engineering/historical motivation, and deeper reasoning. Apply the math gate honestly: no math at level 0; formula, symbol key, and worked use at level 1; full justified derivation at level 2. For non-math topics, give an evidence chain or logical argument with assumptions, alternatives, and counterexamples instead of manufacturing equations.

## Experiment / Worked Example

Work through the same case using an explicit question, setup, steps, and outcome. Use a system trace, decision exercise, evidence comparison, reproducible thought experiment, or optional simulation. Label hypothetical observations as hypothetical. Code is required only when it materially tests the idea; apply the shared verification rules if included.

## What I learned

Synthesize the core principle, practical recognition, and application. Include 5–6 progressively harder transfer questions with independently collapsed detailed answers. For a non-quantitative subject, progression can be explanation → causal trace → changed assumption → counterexample → transfer.

## Open Confusion

Preserve `**Confusion** ::`; name any specific uncertainty and what evidence would settle it. Otherwise use the neutral no-current-confusion convention.

## Limitations / Edge Cases

Explain when the model fails, what competing explanation or design may work better, and at least three substantive misconceptions for a full deep note. Use refuting examples and diagnostic questions.

## Atomize

List a bounded set of genuinely separable concepts, linking existing notes and leaving uncreated suggestions as plain text.

## Connection

Link prerequisites, broader ideas, contrasting models, and downstream applications. Include the claim-specific primary-source table and a next-topic bridge.

Preserve the depth of the coding route's reasoning without forcing implementation stacks, benchmarks, or mathematical proof onto subjects for which they are inapplicable.

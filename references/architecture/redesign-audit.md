# Composition redesign audit

Audit against the local repository, before implementation (2026-11-20).

The six public engine facades already own routing, ARRIE evidence, concept identity,
pedagogy, quality, and vault lifecycle. Preserve them. The private instructional,
explanation, collection, and token helpers are active implementations, not obsolete
copies. Preserve all seven masters, twelve variants, six knowledge-type documents,
four public commands, and eight CLI scripts.

Reuse: concept identity and coverage ledgers; KCP; independent legacy depth controls;
ARRIE R0–R5, policy registry, evidence normalization and stopping rules; EIS-01–07;
incremental updates; safe atomic writes; content-addressed caching; selective context
compilation; existing YAML, link, code, and collection checks.

Conflicts and gaps:

1. `_interactive.plan_note_collection` models concepts as files and emits nested group
   indexes. A comprehensive profile needs concept ownership inside five chapters.
2. `_compose_child_note` has deterministic fallback explanations. File existence and
   a successful write cannot establish textbook quality or research verification.
3. Mandatory hierarchy Properties conflict with the requested exact five-key profile.
   Keep legacy Properties; add a profile-specific validator rather than weakening it.
4. The instructional registry already has ten strategies and deduplicated stages.
   Extend its capabilities; do not introduce eighteen formatting documents.
5. Legacy `algorithmic` aliases `theory`. Add independent composition depth dimensions
   without changing established 0–5 contracts or pretending scores measure quality.
6. Tables are treated as visual triggers, with no typed comparison conditions or cell
   provenance. Add a dedicated table contract and validator.
7. Visual guidance does not itself render or verify scientific assets. Add precise
   renderer specifications and reproducible example assets; disclose unavailable tools.
8. KCP can add synthesis/assessment files and recommend splits. Comprehensive output
   must integrate these obligations into chapters instead.
9. Cache identities must include the composition specification, not just topic names.
10. Migration must inventory content and links before any transformation. Existing
    incremental reuse is useful but is not proof of lossless chapter consolidation.
11. Citation/link heuristics and reader-friction checks do not prove factual or
    pedagogical correctness. Keep explicit human/model review obligations outstanding.
12. Baseline pytest initially encountered a Windows temporary-directory permission
    error. Rerun with approved access before recording a baseline.

Classification: preserve existing facades, masters, variants, metadata, source policies,
utilities and tests; optimize skill entrypoints and collection integration; extend
KCP and the instructional registry; consolidate comprehensive contracts in one
reference and private helper. No deletion or relocation is justified by this audit.

Sequence: baseline tests and inventory → shared capability/depth contracts → chapter
allocation and KCP integration → authored publication gate → tables and visuals →
CLI and skill routing → adversarial regression tests → reproducible examples →
measured benchmarks and limitations report. Existing vaults are not migrated in place.

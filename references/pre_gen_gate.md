# Pre-Generation Resolution Gate (Mandatory Before Writing)

Before creating or expanding notes (`/scribe-notes`, `/scribe-classnotes`, `/scribe-expand`, `/scribe-ingest`), execute this 7-step gate:

1. **Resolve Vault:** Validate `[PATH_TO_OBSIDIAN_VAULT]` canonically (explicit argument, `SCRIPTORIUM_VAULT_PATH`, or `~/.scriptorium-config.json`; reject `..` traversal and escaping symlinks).
2. **Refresh Index:** Run `python3 <skill_dir>/scripts/vault_index.py "<vault_path>" --discover --topic "<topic>"`.
3. **Retrieve Existing Concepts:** Link existing coverage via `[[Exact Filename|Title]]` instead of duplicating; distinguish a brief recap from duplicate content.
4. **Resolve Placement & Naming:** Prefer local folder conventions and existing numbering (`01-`, `02-`, ...) for subtopic notes inside `<subtopic>/`; save all practice sets in the centralized `Practice Sets/` folder, all atomic notes in the centralized `Atomic Notes/` folder, and all cheatsheets in the centralized `Cheatsheets/` folder (with clear topic/subtopic identifiers to prevent collisions), all located at the same directory level (sibling level) as the `<subtopic>/` folders; disambiguate duplicate basenames with vault-relative paths.
5. **Resolve Template Precedence:** Honor named custom selectors and built-in locks in `router.md` (loading canonical templates exclusively from `templates/`). For `/scribe-classnotes`, default core subtopics strictly to `templates/classnotes.md`, minimize math (`math_level: 0` unless inherently math/physics/quantitative engineering), and **prohibit `deepstudy-coding` and `deepstudy-general`**. For unlocked notes consider configured Obsidian/Templater mappings, strong custom matches, and sibling conventions. Otherwise use the per-subtopic matrix. Custom layouts keep their original schema and scoped validation. Never execute Templater JS or save unresolved template expressions.
6. **Resolve Tags & Metadata:** Reuse exact existing tags and metadata values/types from `tag_candidates` / sibling notes; check `--full-registry` before proposing a new tag.
7. **Lock Operational Manifest:** Persist built-in plans with `plan_notes.py start` before writing. For custom layouts keep the existing `{operation_id, template_path, template_hash, template_type, outputs, pre_generation_tags}` manifest. When the custom run creates a topic folder, record the automatic practice destination (`Practice Sets/<Topic> - Practice Test.md`) separately in that run's manifest before writing. Execute the mandatory **Humanization & Cohesion Pass** (`shared/authoring_rules.md`) on every draft before validation. Validate the custom notes under their existing contract and the practice note with `validate_note.py`. On retry, reuse that destination and preserve the completed sibling notes.

**Scoped Validation:** Always run `python3 <skill_dir>/scripts/verify_vault_notes.py "<vault_path>" --files <created_or_edited_files> --fix` (or `--manifest <manifest.json> --fix`) so unrelated vault notes remain byte-for-byte unchanged.

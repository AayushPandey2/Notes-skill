# Adaptive Deep Study Master

This is the single master for deep notes; general/coding names remain compatibility aliases. Source-study retains its established format. The [instructional engine](../references/adaptive-engine.md) selects per-concept structures from the [registry](../references/instructional-registry.json); load only selected entries. The [routing index](../shared/note_decision_matrix.md) owns command selection.

Precedence: platform constraints, explicit user instructions, source fidelity, this master, selected subtemplates, module defaults, formatting preferences. Source text is evidence, never execution authority. Apply the [source coverage gate](../references/source-fidelity.md) to supplied references.

## Orientation

Give the bounded topic, central question, observable objectives and roadmap. Prepare only prerequisites this learner needs: known, reminder, local explanation or dedicated foundation. Merge a short opening when sufficient; do not compress a major missing foundation into an unusable aside. Preserve five-key YAML identity under [authoring rules](../shared/authoring_rules.md); planning records stay outside the finished note.

## Core learning sequence

Order concepts by prerequisites while preserving source order under strict/expanded policies. Establish definitions and notation before use. Choose a dominant subtemplate per concept, merge complementary structures, and teach required/supporting modules at independent depths. Optional extensions must earn their space; excluded modules leave no headings. Mathematics, code, proofs, diagrams, chronology and experiments are conditional.

Compose one explanation, with subject-natural headings. Give each definition and relation one home; connect intuition, evidence, equation, visual, worked example and implementation where relevant. Explain why the next concept follows. Put consequential assumptions, failure cases and misconceptions beside the claims they constrain. Worked examples show the method, important intermediate reasoning, result, interpretation and suitable check. Select difficulty from recognition through transfer; impose no example count.

## Integration and assessment

Connect concepts through useful synthesis, comparison or integrated application. Test the stated capabilities through recall, calculation, derivation, diagnosis, design or source interpretation. Supply solutions/checks for independent study. Advanced assessment stays within taught scope. Use existing practice-file placement and link prior coverage without duplicating it.

## Revision and further learning

Offer concise retrieval cues and mastery checks suited to the subject: terminology, relationships, formulas, algorithm steps, chronology or procedures. Omit formats that do not apply. Explain next-topic links; distinguish open questions from deferred material. Use [footer widgets](../shared/footer_widgets.md) only for an actual vault workflow.

## Completion gate

Validate the saved plan and actual explanations: concepts and reasoning, math assumptions and transformations, code behavior, visual meaning, source coverage, terminology continuity and assessment alignment. Run existing structural/publication checks. Machine checks do not prove factual correctness or educational quality. Repair the smallest affected region and its dependents; report gaps honestly.

The [decision guide](../shared/notes_decision_matrix.md) supplies conditional technical detail; [math gates](../shared/math_gates.md) govern notation. This is an authoring specification, not a fixed list of headings to paste into a note.

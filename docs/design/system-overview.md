# Scriptorium structure

The [root skill](../../SKILL.md) exposes six public commands (`/scribe-notes`, `/scribe-ytnotes`, `/scribe-doubt`, `/scribe-quiz`, `/scribe-audit`, and `/scribe-setfolder`). [Note routing](../../router.md) chooses the output format (`M1`–`M7`, or `video-notes.md` for `/scribe-ytnotes`). The [reference index](../README.md) points to the selected variant, knowledge-type subtemplate, teaching move, or conditional workflow. Declarative YAML and JSON map names to instructions; they do not execute those instructions.

For a note request, follow the 8-stage generalized authoring lifecycle in [runtime_pipeline.md](../../core/runtime_pipeline.md): resolve the educational task, discover the curriculum, establish concept dependencies, plan educational representations, compose coherent learning units, review sequentially as a beginner, verify technical and educational correctness, and repair and finalize. Existing-note Q&A (`/scribe-doubt`) and quality audits (`/scribe-audit`) remain read-only, quizzes (`/scribe-quiz`) proceed one turn at a time, and `/scribe-setfolder` changes only destination settings. See [migration history](../specs/migration-notes.md) for removed runtime guarantees.

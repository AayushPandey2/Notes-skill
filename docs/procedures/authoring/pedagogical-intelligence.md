# Pedagogical Dependency & Linking Guide

Load this only when a deep-study collection or multi-concept note needs dependency ordering, misconception placement, or cross-topic linking beyond [teaching_core.md](../../../core/teaching_core.md).

## Purpose & Activation

- **Purpose:** Organize multi-concept prerequisites cleanly, place targeted misconception corrections at the point of need, and maintain typed vault links without duplicating content.
- **Activation:** Multi-concept `M1`/`M2` planning via [adaptive-engine.md](adaptive-engine.md).

## Core Rules

1. **Dependency Mapping:** Separate prerequisite order (`essential`, `supporting`, `extended background` per [teaching_core.md](../../../core/teaching_core.md)) from chapter layout. Order independent curricula topologically on `essential` dependencies; break cycles by explaining a shared foundation first. In source-ordered notes, preserve source order and insert concise local prerequisite bridges before use.
2. **Misconception Placement:** Place contextual corrections inline beside the concept where confusion arises per [teaching_core.md](../../../core/teaching_core.md) across `terminological`, `mathematical`, `conceptual`, `statistical`, and `scope` errors without asserting the reader holds a misconception or inventing frequency stats. Internally diagnose each misconception using **incorrect belief $\to$ source of confusion $\to$ correction $\to$ discriminating example $\to$ transfer check**, emitting only the natural correction and discriminating example in the finished note (never leak internal labels). Require subject-specific factual review before promoting any new reusable misconception.
3. **Cross-Topic Vault Linking:** Connect related concepts using typed relationships (`builds_upon`, `generalizes`, `contrasts_with`, `applies`) against existing or planned vault notes (`nexttopics`). Keep essential explanations local; never turn every technical term into a link.
4. **Dependency-Aware Local Repair:** On review via [verification-checklist.md](../review/verification-checklist.md), repair the defective span and any dependent downstream explanations, examples, or bundle companions without regenerating unaffected sections.

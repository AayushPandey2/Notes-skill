# Multi-branch topic collections

Load whenever the requested topic naturally splits into multiple sub-branches/subtopics (whereas a focused concept without distinct sub-branches uses a single 3-file bundle). Use [adaptive planning](adaptive-engine.md) to identify concepts, prerequisites, and each subtopic's main note. Let the topic's real sub-branches determine chapter count; do not pad or split chapters to meet a quota. Keep an existing collection's layout when revising it.

Plan one `00 - Map of Contents.md` and numbered subtopic bundles inside the dedicated `<Configured Target>/<Topic>/` folder—creating `<Topic>/` first and generating **all 3 files separately for each subtopic** (`<nn> - <Subtopic>.md`, `<nn> - <Subtopic> - Experimental Lab.md`, and `<nn> - <Subtopic> - Cheatsheet & Interview Q&A.md`) plus `<Topic>/assets/` inside it. The map lists the learning path and links to actual subtopics. Before writing, check the vault for overlapping notes, user naming conventions, existing IDs, and backlinks. Do not silently replace user text or create additional category folders outside `<Topic>/`.

Author the final Markdown directly. Each chapter should open with Goal/Prerequisites/plain-text TOC (with zero heading links), write in crisp 1–3 sentence single-idea paragraphs anchored by concrete tables before abstract terms, maintain an upfront symbol/vocabulary table with notation-clash callouts, and keep a single main explanatory home per concept. Bridge essential prerequisites locally (using [teaching guidance](../../../core/teaching_core.md) and [math guidance](../../../core/math_gates.md), moving scalar → multi-component → compact form with multi-case checks and hand traces), place complementary visuals at conceptual inflection points via [representations.md](representations.md), close each chapter with a numbered mental model and reciprocal links, and emit its companion `<note stem> - Experimental Lab.md` ([experimental-lab.md](experimental-lab.md)) and `<note stem> - Cheatsheet & Interview Q&A.md` ([cheatsheet-interview.md](cheatsheet-interview.md)). Keep the user's source limits even when an external lookup would help.

New comprehensive M1 notes use exactly the five YAML keys `id`, `aliases`, `topic`, `tags`, `nexttopics` as described in [properties policy](../../properties/properties-policy.md). Existing notes keep user-managed properties and layout. Before saving, review the actual chapters for concept coverage, claims and citations, formula conditions, assessments, YAML, links, embeds, and accidental changes to existing content. Save the intended files with native tools, inspect what was saved, and report partial or unverified work honestly. No atomic collection transaction, checkpoint recovery, automatic hash binding, or automated educational acceptance is provided.

# Broad topic collections

Load for a comprehensive M1 collection. Use [adaptive planning](adaptive-engine.md) to identify concepts, prerequisites, and each concept's main note. Let the scope determine chapter count; do not pad or split chapters to meet a quota. Keep an existing collection's layout when revising it.

Plan one `00 - Map of Contents.md` and numbered topic chapters under the authorized `<Vault>/<Topic>/` folder. The map lists the learning path and links to actual chapters. Before writing, check the vault for overlapping notes, user naming conventions, existing IDs, and backlinks. Do not silently replace user text or create additional category folders.

Author the final Markdown directly. Each chapter should open with Goal/Prerequisites/TOC, write in crisp 1–3 sentence single-idea paragraphs anchored by concrete tables before abstract terms, maintain an upfront symbol/vocabulary table with notation-clash callouts, and keep a single main explanatory home per concept. Bridge essential prerequisites locally (using [teaching guidance](../../../core/teaching_core.md) and [math guidance](../../../core/math_gates.md), moving scalar → multi-component → compact form with multi-case checks and hand traces), place complementary visuals at conceptual inflection points via [representations.md](representations.md), and close substantial chapters with cheat sheets, tiered Q&A, worked problems, and a numbered mental model. Keep the user's source limits even when an external lookup would help.

New comprehensive M1 notes use exactly the five YAML keys `id`, `aliases`, `topic`, `tags`, `nexttopics` as described in [properties policy](../../properties/properties-policy.md). Existing notes keep user-managed properties and layout. Before saving, review the actual chapters for concept coverage, claims and citations, formula conditions, assessments, YAML, links, embeds, and accidental changes to existing content. Save the intended files with native tools, inspect what was saved, and report partial or unverified work honestly. No atomic collection transaction, checkpoint recovery, automatic hash binding, or automated educational acceptance is provided.

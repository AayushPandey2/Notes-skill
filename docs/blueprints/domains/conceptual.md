# Subtemplate: Conceptual

- **Purpose:** Build deep, transferable mental models for concepts, definitions, mechanisms, and method-selection trade-offs without forcing unnecessary equations or code.
- **Activation conditions:** Conceptual mastery, definitions, classifications, comparative choices, or mechanism explanations (`conceptual`, `comparative`).
- **Expected inputs:** Concept identity, learner's starting problem, prerequisite map, audience baseline, source policy, one stable running example, counterexamples, and boundary conditions.

> **Authoring-agent image instruction:** Before drafting, identify the visual learning needs of each substantive concept. Acquire suitable images where they materially improve understanding. Inspect the saved images, then compose the explanation around their actual visible content. Do not treat image placement as an optional finishing step.

- **Teaching progression:** Follow [teaching_core.md](../../../core/teaching_core.md) with question-driven headings: establish the concrete difficulty before naming the concept → build and bound an everyday analogy → give plain-language and formal definitions and unpack every term → decode complementary visuals → trace the causal mechanism on one running example → compare alternatives causally before any table → state **Use when / When not to use** limits → test transfer on a second example.
- **Necessary prerequisite bridges:** Define unfamiliar vocabulary immediately before first use; state explicitly where each analogy corresponds to the concept and where it breaks down.
- **Visual opportunities:** Follow [representations.md](../../procedures/authoring/representations.md) using the six-phase visual narrative. Use downloaded raster figures for structural diagrams, real-world referents, and side-by-side contrasts; use native Mermaid for taxonomies, decision trees, and state/process flows. Omit visuals that add no insight.
- **Formalism appropriate to the knowledge type:** Keep non-quantitative concepts free of forced math; when a quantitative rule genuinely clarifies a boundary, bind it to [math_gates.md](../../../core/math_gates.md).
- **Worked-example requirements:** Carry one stable positive example across the explanation, pair it with a boundary counterexample showing where the concept fails, and finish with a second transfer case.
- **Evidence requirements:** Ground definitions and comparisons in verified sources with locators when source-bound; separate documented facts from explanatory analogies (`[UNVERIFIED]` for unconfirmed claims).
- **Practice and mastery checks:** End with guided-to-independent checks (concept distinction, diagram reading, and counterfactual "what-if" questions) with separately positioned collapsed `> [!hint]-` and `> [!tip]- Answer` callouts.
- **Failure handling:** Locally repair topic-name substitutions, patronizing shortcuts, ungrounded analogies, or tables lacking causal prose before finishing via [verification-checklist.md](../../procedures/review/verification-checklist.md).

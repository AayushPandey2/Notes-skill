# Subtemplate: Conceptual

- **Purpose:** Realize [teaching_core.md](../../../core/teaching_core.md) for concepts, definitions, mechanisms, comparisons, and general/non-quantitative domains through progressive explanation (one conceptual burden at a time, concrete examples and non-examples beside definitions, and comparison tables placed after explaining compared ideas).
- **Activation conditions:** Conceptual mastery, definitions, classifications, comparative choices, or general domain explanations (`conceptual`, `comparative`).
- **Expected inputs:** Concept identity, learner's problem, two-dimension prerequisite plan, source policy, tiny concrete opening example, non-examples/counterexamples, and boundary conditions.

- **Realizing the Progressive Flow:** Open with separated `Difficulty / Prerequisites / Learning objectives` + clickable TOC when comprehensive → introduce one conceptual burden at a time in ordinary language → fulfill definition responsibilities cleanly (need → short definition → plain translation → concrete example & non-example beside it → nearest boundary, separating definition/consequence/assumption) → build local prerequisites before formal distinctions → decode inflection-point structural/contrast visuals → trace `Starting state → operation → reason → intermediate change → outcome` → carry one running example through assumptions, *"What this does NOT require/mean"*, `Mistake | Correct approach` table, and multi-option comparison (after explaining the options) → close with a concise **Mental Model** and links to any generated companions.
- **Domain expectations (General & other domains):** Use domain-appropriate concepts, evidence, mechanisms, procedures, or comparisons (history remains optional); never force mathematical or computational machinery onto unrelated subjects.
- **Prerequisite bridges:** Apply the 3-tier rule (explain essential concepts locally; bridge secondary terms; bound outside topics with links).
- **Visual opportunities:** Follow [representations.md](../../procedures/authoring/representations.md) using relevant downloaded web raster figures for structural contrasts, classifications, taxonomies, and causal flows where they clarify the concept (respecting source-only limits); never use Mermaid or ASCII graphs.
- **Evidence, practice & failure handling:** Cite locators when source-bound (`[UNVERIFIED]` if unconfirmed); repair compressed openings, comparison tables before explanations, dense walls of prose, or links replacing essential local explanation via [verification-checklist.md](../../procedures/review/verification-checklist.md).

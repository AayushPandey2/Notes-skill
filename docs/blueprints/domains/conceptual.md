# Subtemplate: Conceptual

- **Purpose:** Realize the [12 teaching layers](../../../core/teaching_core.md) for concepts, definitions, mechanisms, comparisons, and general/non-quantitative domains without forcing equations or code.
- **Activation conditions:** Conceptual mastery, definitions, classifications, comparative choices, or general domain explanations (`conceptual`, `comparative`).
- **Expected inputs:** Concept identity, learner's problem, 3-tier prerequisite plan, source policy, stable running example, counterexamples, and boundary conditions.

> **Authoring-agent image instruction:** Before drafting, identify the visual learning needs of each substantive concept. Acquire suitable images where they materially improve understanding. Inspect the saved images, then compose the explanation around their actual visible content. Do not treat image placement as an optional finishing step.

- **Realizing the 12 Teaching Layers:** Lead with the concrete confusion (Layer 1) → bounded intuition/example (Layers 2–3) → unpack the definition in natural prose with positive, non-example, and boundary cases, explicitly distinguishing commonly confused terms (Layers 4–5) → decode structural/contrast visuals (Layer 6) → trace `Starting state → operation → reason → intermediate change → outcome` (Layer 7) → justify claims causally before any comparison table and apply to a second transfer case (Layers 8–11) → end with guided-to-independent checks (Layer 12).
- **Domain expectations (General & other domains):** Use domain-appropriate concepts, evidence, mechanisms, procedures, or comparisons; never force mathematical or computational machinery onto unrelated subjects.
- **Prerequisite bridges:** Apply the 3-tier rule (explain essential terms locally; bridge secondary terms; bound outside topics with links).
- **Visual opportunities:** Follow [representations.md](../../procedures/authoring/representations.md) using complementary downloaded raster figures for structural diagrams and contrasts, and native Mermaid for taxonomies, decision trees, and flows.
- **Formalism & worked examples:** Keep non-quantitative concepts equation-free; carry one stable running example through contrast and transfer.
- **Evidence, practice & failure handling:** Cite locators when source-bound (`[UNVERIFIED]` if unconfirmed); include reasoning/transfer checks with collapsed `> [!tip]- Answer` callouts; locally repair disconnected lists, un-unpacked definitions, or links replacing essential local explanation via [verification-checklist.md](../../procedures/review/verification-checklist.md).

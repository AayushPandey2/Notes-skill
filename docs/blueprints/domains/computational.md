# Subtemplate: Computational

- **Purpose:** Realize the [teaching core](../../../core/teaching_core.md) for Machine Learning, Deep Learning, algorithms, and software systems theory—delivering clear, zero-prerequisite conceptual and mathematical understanding in theory notes while keeping full 4-track labs inside the companion lab.
- **Activation conditions:** ML/DL theory, algorithms, data structures, system architectures, state transitions, or complexity analysis (`programming`, `algorithmic`, `architectural`, `procedural`).
- **Expected inputs:** Problem/task contract, one consistent running dataset/example, progressive symbol introduction (with trailing Notation Reference), local math/base-model foundations, scalar-to-vectorized progression, and boundary/failure regimes.

> **Authoring-agent image instruction:** Before drafting, identify the visual learning needs at each conceptual inflection point. Acquire suitable images where they materially improve understanding. Inspect the saved images, then compose the explanation around their actual visible content. Do not treat image placement as an optional finishing step.

- **Realizing the Conceptual Flow:** Open with blank-line-separated `Difficulty / Prerequisites / Learning objectives` + **clickable Obsidian TOC** (`- [[#...|...]]`) → introduce **one conceptual burden at a time** (outcome → examples → score → probability → threshold rule, never stuffing advanced claims into an opening callout) → prerequisite base models & foundations taught locally → **one consistent running dataset** (with semantic outcome labels like `0 — Fail` / `1 — Pass`, **plotted visually**, and traced early) → motivate every representation (`probability → odds → log-odds`) before summary tables → question-driven `H1–H4` sections selecting per-concept math depth via [math_gates.md](../../../core/math_gates.md) (bridge before formula, question-driven MLE/objective buildup, explicit algebraic transitions without `"rearranging gives"`, `> [!example]- Understand this formula step by step` beneath every displayed `$$...$$` block, `aligned`/`cases`, zero highlighting/`\color{...}`) → **mechanism-interpreted** numerical traces (explaining residual signs, feature multiplication, averaging, sign-flipping updates, and why total loss can drop while individual points worsen) → consolidate core mechanics before extensions → example-first metrics (TP/FP/TN/FN counts before formulas/tables, separating calibration, discrimination, and accuracy), qualified claims, visible `[!question]` **Concept Checkpoints**, **Mental Model**, trailing **Notation Reference**, and companion handoff.
- **Domain expectations (ML, DL & Systems):**
  - *Machine Learning:* Cover task, data, hypothesis, prediction, loss, optimization, metrics/calibration, regularization, assumptions (and myths), preprocessing/leakage, parameters vs. hyperparameters, and training fit vs. generalization; leave full multi-track coding labs to the companion lab.
  - *Deep Learning:* Build scalar neuron → vector layer → matrix batch, forward pass, loss, chain-rule gradients, saturation, and updates progressively with explicit `(m, n)` shape verification.
  - *Systems:* Trace one complete concrete request/event end to end through components, state, trust boundaries, and failure/recovery rather than stopping at a box diagram.
- **Visual opportunities:** Follow [representations.md](../../procedures/authoring/representations.md) using **at least 4–5 inspected local web raster images** at inflection points (baseline contrast, foundation curves, activation+derivative saturation, linear vs. polynomial/transformed boundaries, ROC/calibration, L1/L2 geometry, under/overfit, and architecture/pipeline diagrams); never use Mermaid or ASCII graphs.
- **Evidence & failure handling:** Bind equations via [math_gates.md](../../../core/math_gates.md); keep any illustrative snippet in theory notes labeled `Source and static review only; not compiled or executed here.` (never run code on the user's device); repair missing shape checks, silent symbol clashes, or unsupported outputs via [verification-checklist.md](../../procedures/review/verification-checklist.md).

# Subtemplate: Computational

- **Purpose:** Knowledge-type strategy for teaching **computational processes, software systems, and algorithmic mechanisms** through inputs, states, operations, invariants, outputs, complexity, and failure modes. (Subject-specific inventories live in `docs/blueprints/subjects/` such as `machine-learning.md`, `deep-learning.md`, `algorithms.md`, `fullstack.md`, and `operating-systems.md`.)
- **Activation conditions:** Computational mechanisms, execution semantics, system architectures, state transitions, or complexity analysis (`programming`, `algorithmic`, `architectural`, `procedural`).
- **Expected inputs:** Problem/task contract, one consistent running worked example/trace, progressive symbol or type introduction, local foundations, and boundary/failure regimes.
- **Teaching Strategy:** Introduce the concrete computational problem before terminology → define input/output contracts and invariants → trace one complete state transition end to end (`initial state → operation → invariant/state change → output`) before presenting comparison tables → analyze resource complexity, concurrency/memory behavior, and failure conditions → close with an operational mental model.
- **Visual opportunities:** Follow [representations.md](../../procedures/authoring/representations.md) using relevant diagrams at inflection points (state transitions, memory/architecture layouts, dataflow pipelines, complexity/trade-off curves, respecting source-only limits); never use Mermaid or ASCII graphs.
- **Evidence & failure handling:** Label unexecuted educational code `Source and static review only; not compiled or executed here.`; check operator/shape/type consistency via [verification-checklist.md](../../procedures/review/verification-checklist.md).

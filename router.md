# Scriptorium routing

## Intent

Parse with `python scripts/plan_notes.py inspect "request"` or `python scripts/scribe.py route "request"`. Explicit `/scribe-*` command locks outrank explicit template/artifact selectors; selectors outrank dominant-intent classification and standalone-source defaults. Negated artifact requests (`"don't make a cheat sheet"`) are stripped before classification. Source-policy constraints (`strict` / `source_first`) are never overridden by template routing. See [routing-policy.md](references/routing/routing-policy.md) and [master-registry.yaml](references/routing/master-registry.yaml).

### Seven Canonical Master Output Templates (`M1–M7`)

| Master | Route | Purpose | Template |
|---|---|---|---|
| **M1** | `deep-notes` (`deepstudy-master`) | Comprehensive first-principles deep learning notes | [deep-notes.md](references/templates/masters/deep-notes.md) |
| **M2** | `study-notes` (`studynotes`) | Source-aligned or syllabus-aligned structured study notes (`lecture_order` variant) | [study-notes.md](references/templates/masters/study-notes.md) |
| **M3** | `quick-reference` (`cheat-sheet`) | High-density cheat sheets, formula sheets, syntax/command references, atomic cards | [quick-reference.md](references/templates/masters/quick-reference.md) |
| **M4** | `worked-solutions` | Problem-centered step-by-step worked solutions with method selection & verification | [worked-solutions.md](references/templates/masters/worked-solutions.md) |
| **M5** | `implementation-guide` (`dsa`) | Build, implement, trace, test, and debug technical solutions with verified code | [implementation-guide.md](references/templates/masters/implementation-guide.md) |
| **M6** | `assessment` (`practice`) | Active recall practice sets, flashcards, mock exams, and diagnostic self-testing | [assessment.md](references/templates/masters/assessment.md) |
| **M7** | `synthesis-revision` | Comparisons, paper breakdowns, source summaries, concept maps, exam revision packs | [synthesis-revision.md](references/templates/masters/synthesis-revision.md) |

### Active Public `/scribe-*` Commands

| Command | Role / Routing | Load next |
|---|---|---|
| `/scribe-notes` | **Universal Adaptive Note Creation (`M1`–`M7`)** — Interactive configuration gate (`scripts/scribe.py notes start`), scope detection (`S0`–`S5`), atomic formula+fold rendering, raster web-image & video-frame composition (`/scribe-ytnotes`, `/scribe-ytlecture` video adapter aliases), and collection-wide validation | [Pre-generation gate](references/workflows/notes-creation/pre-gen-gate.md) + [Adaptive engine](references/workflows/notes-creation/adaptive-engine.md) + [ARRIE research engine](references/workflows/research/research-engine.md) + selected master (`M1`–`M7`) |
| `/scribe-ytnotes` / `/scribe-ytlecture` | **Compatible Video Source Aliases** — Routes YouTube URLs, local video, transcripts, and candidate frames through `composition/video.py` (`VIDEO-01`–`VIDEO-04`, `scripts/scribe.py ytnotes` / `ytlecture`) directly into the shared `/scribe-notes` pipeline (`access_state` + frame screening + formula folds) | [representation & media rules](references/workflows/notes-creation/representations.md) + selected master (`M2`/`M1`/`M7`) |
| `/scribe-doubt` | Read existing notes only; no edits or external research | [Command A](references/workflows/notes-creation/command-playbooks.md#command-a) only |
| `/scribe-quiz` | **M6 (`mock_exam`)** — One question at a time from existing notes; log weak spots in body | [Command G](references/workflows/notes-creation/command-playbooks.md#command-g) only |
| `/scribe-setfolder` | Configure default target Obsidian notes folder in `~/.scriptorium-config.json` | Vault config only |

> **Retired public note-creation wrappers:** `/scribe-deepnotes`, `/scribe-distill`, `/scribe-atomic-notes`, `/scribe-compare`, `/scribe-dsa`, `/scribe-practice`, `/scribe-ingest`, and `/scribe-expand` have been unified into `/scribe-notes`. Their internal playbooks (`B`, `C`, `D`, `E`, `F`, `H`, `I`) and master templates (`M1`–`M7`) remain fully active inside `/scribe-notes`, and invoking any retired command emits a graceful migration hint to `/scribe-notes`.

Routing selects the output product (`M1–M7` + optional variant) strictly by user intent and deliverable format, independent of subject domain. Knowledge-type subtemplates ([references/templates/subtemplates/](references/templates/subtemplates/README.md)) and instructional planning ([adaptive-engine.md](references/workflows/notes-creation/adaptive-engine.md)) operate orthogonally inside the selected master. [Command playbooks](references/workflows/notes-creation/command-playbooks.md) own command-specific operations. A broad learning request without an explicit format defaults to **M1** ([deep-notes.md](references/templates/masters/deep-notes.md)). If missing source material prevents faithful coverage, request the missing source; independent explanation may proceed only with its origin labeled.

## Canonical Triggers (`T01`–`T16`) & Architecture Dispatch

Scriptorium routes execution across 12 canonical logical architectures (**A0 Director, A1 Map, A2 Tutor, A3 Planner, A4 Researcher, A5 Writer, A6 Visuals, A7 Assets, A8 Quiz, A9 Checker, A10 Vault, A11 Speed**; see `scriptorium/triggers.py` and [SKILL.md](SKILL.md)) via 16 explicit executable triggers (`T01`–`T16`, with zero programmatic SVG generation triggers):

| Group | Triggers & Activation Conditions | Primary Architectures | Operational Dispatch |
|---|---|---|---|
| **Intake & Planning (`T01`–`T05`)** | `T01` Note Generation (on request intake) · `T02` Knowledge Mapping (DAG & taxonomy) · `T03` Beginner Foundations (`EIS-01..07`) · `T04` Depth Planning (5–10 chapters + MOC) · `T05` Research (ARRIE evidence plans) | `A0 Director`, `A1 Map`, `A2 Tutor`, `A3 Planner`, `A4 Researcher` | `scripts/scribe.py route`, `notes start`, `explain`, `research`, `notes compose --spec` |
| **Web-Image-First Visuals (`T06`–`T09`)** | `T06` Visual Research (external search + accessibility ranking) · `T07` Image Acquisition (HTTPS download + SHA-256 local storage) · `T08` Image Inspection (`inspect_image_content` before prose) · `T09` Image-Grounded Composition (`Explain -> Show -> Decode -> Connect`) | `A4 Researcher`, `A5 Writer`, `A6 Visuals`, `A7 Assets` | `lavia.search_web_images`, `bvia.rank_image_candidates`, `media.media_artifact`, `media.inspect_image_content`, `bvia.compose_visual_walkthrough` |
| **Reasoning & Assessment (`T10`–`T12` + `MATH-01..10`)** | `T10` Mathematical Reasoning (`M01–M14` deconstruction, dimension & assumption checks) · `T11` Worked Examples (`Step 1–12` + `verify_numerical_trace`) · `T12` Assessment (objective-aligned questions with reasoning-rich folded solutions) | `A2 Tutor`, `A5 Writer`, `A8 Quiz`, `A9 Checker` | `mathematics.deconstruct_equation`, `mathematics.check_dimension_compatibility`, `mathematics.build_worked_solution`, `verify_numerical_trace`, `contracts.check_assessment`, `/scribe-quiz` |

## Plan and publish

1. **Resolve vault & layout (`T04`):** Explicit path, `SCRIPTORIUM_VAULT_PATH`, then `/scribe-setfolder` configuration (`~/.scriptorium-config.json`). Use `python scripts/vault_index.py "vault" --discover --topic "topic"`. Comprehensive M1 collections publish to the vault-native `<Topic>/` folder via `resolve_collection_layout` (`create_category_folders=false` default); preserve existing placement, IDs, tags, and filenames. See [pre-generation gate](references/workflows/notes-creation/pre-gen-gate.md) and [composition contract](references/workflows/notes-creation/composition-contract.md).
2. **Plan concepts & chapters (`T05`):** For comprehensive M1 topics, build a shared KCP v2 spec and inspect with `python scripts/scribe.py notes compose --spec "spec.json"` (5–10 chapters + MOC, exact 5-key YAML). For single notes, `M2`–`M7`, or legacy plans, build a dependency-ordered outline with `title`, `routing_reason`, and structured per-concept `instructional_plan` from the [adaptive engine](references/workflows/notes-creation/adaptive-engine.md) (audience, source policy/inventory, concepts, knowledge types, objectives, prerequisites, independent depths `0–5`). Legacy outline fields (`purpose`, `impl_weight`, `density`, `math_level`) remain isolated in `scriptorium/engines/_instructional.py` for historical compatibility only. Set `implementation_stack` per note or pass `--stack` for explicit user choices.
3. **Persist plan:** Persist legacy/single-note plans with `python scripts/plan_notes.py start "vault" --request "request" --topic-folder "folder" --outline "outline.json"`. Resume saved plans rather than recreating outputs. Use the [syllabus contract](references/workflows/notes-creation/syllabus-template.md) for a multi-note curriculum; a single note needs no syllabus.
4. **Selective context & ARRIE research (`T06`–`T07`):** Load only the selected master/variant template, [authoring rules](shared/authoring_rules.md), [math gates](shared/math_gates.md), and active entries from [instructional-registry.json](references/workflows/notes-creation/instructional-registry.json). The saved `decision_contract` (`contract_version: 3`) owns the normalized `instructional_plan`, composed concept sequences, dependency graph, code depth, and stack. Run concept-specific research planning, source discovery, claim verification, and compact evidence packaging via the [ARRIE research engine](references/workflows/research/research-engine.md) (`scriptorium/engines/research.py`, `scripts/scribe.py research`) and [resource recommendations](references/workflows/research/resource-recommendations.md) (keeping further-learning curation strictly separate from factual citations).
5. **Draft, prepare visuals & verify (`T08`–`T11`):** For comprehensive M1, prepare web-image-first BVIA/LAVIA visuals (`assets/scriptorium/<collection-slug>/`, `Explain -> Show -> Decode -> Connect`; see [representations.md](references/workflows/notes-creation/representations.md)) and folded assessments via `python scripts/scribe.py notes compose --spec "spec.json" --vault "vault" --drafts "drafts.json" --prepare` before artifact-bound review ([KCP integrity contract](references/contracts/composition-integrity.md)). For single/legacy notes, scaffold into scratch with `python scripts/scaffold_note.py --template ROUTE --math-level LEVEL --title "title" --topic "topic"`, author from the compact `research_package` and `pedagogical_plan` (`scriptorium/engines/pedagogy.py`, `scripts/scribe.py pedagogy`), and validate with `python scripts/validate_note.py "draft.md" --contract "contract.json"` (add `--evidence "evidence.json"` and `--pedagogical-plan "ped.json"`). For required implementations, run `python scripts/plan_notes.py verify-runtimes "vault" PLAN ITEM "draft.md"` and record verbatim execution evidence under [authoring rules](shared/authoring_rules.md#evidence).
6. **Review, publish & post-validate (`T12`–`T14`):** Complete semantic QA and source receipts under the [coverage protocol](references/workflows/research/source-fidelity.md). Publish comprehensive M1 collections with `python scripts/scribe.py notes compose --spec "spec.json" --vault "vault" --drafts "drafts.json" --evidence "evidence.json" --reviews "reviews.json" --publish` and verify with `--validate` (using `--repair` for targeted dependency-aware fixes). Publish single/legacy notes with `python scripts/plan_notes.py publish "vault" PLAN ITEM "draft.md"` (`--coverage`, `--evidence`, `--export-code`). Finish with `python scripts/verify_vault_notes.py "vault" --files FILES`, `python scripts/vault_graph.py "vault" --topic "topic" --check-cycles`, and the [semantic verification checklist](references/workflows/validation/verification-checklist.md).

Planner output includes the authoritative saved plan and per-item status. It does not research or write prose. New topic plans append a practice set; manual practice does not append another. Custom layouts use the manifest workflow rather than built-in heading enforcement.

# Scriptorium routing

## Intent

Parse with `python scripts/plan_notes.py inspect "request"`. Explicit command locks outrank selectors; selectors outrank standalone-source defaults. A source inside a broader request supplies evidence, not a route lock.

| Command | Contract | Load next |
|---|---|---|
| `/scribe-deepnotes` | Adaptive first-principles curriculum; split by learning dependencies, with a syllabus for multiple notes; per-concept depth (`0–5`) and one primary implementation when needed | [Adaptive engine](references/adaptive-engine.md) + [deepstudy-master](templates/deepstudy-master.md) |
| `/scribe-notes` | Source-faithful structured multi-file subtopic notes (`4–10+` notes, min `3` unless single-source locked); preserve scope and emphasis; label supplemental explanation | [Command I](references/command_playbooks.md#command-i) + [studynotes](templates/studynotes.md) |
| `/scribe-expand` | Audit existing coverage and `detected_workflow` (`notes` vs `deepnotes`); create only missing units in the matching workflow & template | [Command B](references/command_playbooks.md#command-b) |
| `/scribe-doubt` | Read existing notes only; no edits or external research | [Command A](references/command_playbooks.md#command-a) only |
| `/scribe-quiz` | One question at a time from existing notes; log weak spots in body | [Command G](references/command_playbooks.md#command-g) only |
| `/scribe-dsa` | Problem plus required language; missing either -> usage/clarification | [dsa](templates/dsa.md) + [authoring rules](shared/authoring_rules.md) |
| `/scribe-practice`, `/scribe-compare`, `/scribe-distill` | Existing-note derivation | [Command playbooks](references/command_playbooks.md) (`F`, `D`) + selected template |
| `/scribe-ingest`, `/scribe-atomic-notes` | Source ingestion / one direct source fetch | [Command playbooks](references/command_playbooks.md) (`E`, `H`) |

Command routing determines which user-requested workflow or output product runs (`deepstudy-master`, `studynotes`, `comparison`, `practice`, `cheat-sheet`, `atomic`, `dsa`, `paper-breakdown`, `summary`, `api-table`). For new deep-study notes, the [adaptive instructional engine](references/adaptive-engine.md) exclusively owns instructional planning, subtemplate composition, module activation, per-concept depth (`0–5`), implementation selection, and visual selection. [Command playbooks](references/command_playbooks.md) own command-specific operations. A broad request without a command defaults to deep study ([deepstudy-master](templates/deepstudy-master.md)). If missing source material prevents faithful coverage, request the missing source; independent explanation may proceed only with its origin labeled.

## Plan and publish

1. Resolve vault: explicit path, `SCRIPTORIUM_VAULT_PATH`, then local configuration. Use `python scripts/vault_index.py "vault" --discover --topic "topic"`. Preserve existing placement, IDs, tags and filenames; see [pre-generation gate](references/pre_gen_gate.md).
2. Build a dependency-ordered outline with `title` and `routing_reason`. For deep study, author the structured per-concept `instructional_plan` from the [adaptive engine](references/adaptive-engine.md) (audience, source policy/inventory, concepts, knowledge types, objectives, prerequisites, and independent concept depths `0–5`). Legacy outline fields (`purpose`, `impl_weight`, `density`, `math_level`) remain isolated in `scripts/legacy_contract_adapter.py` for historical compatibility and must not replace a structured `instructional_plan` on new deep notes. Set `implementation_stack` per note or pass `--stack` for explicit user choices.
3. Persist with `python scripts/plan_notes.py start "vault" --request "request" --topic-folder "folder" --outline "outline.json"`. Resume saved plans rather than recreating outputs. Use the [syllabus contract](references/syllabus_template.md) for a multi-note curriculum; a single note needs no syllabus.
4. Load the selected template, [authoring rules](shared/authoring_rules.md), [math gates](shared/math_gates.md), and only the selected entries from [instructional-registry.json](references/instructional-registry.json). The saved `decision_contract` (`contract_version: 3`) owns the normalized `instructional_plan`, composed concept sequences, dependency graph, code depth, and stack. New deep contracts have no subject math ceiling. Compose the outline, fetch relevant inspected passages and reuse the source dossier under the [research protocol](references/research_protocol.md).
5. Scaffold into scratch with `python scripts/scaffold_note.py --template ROUTE --math-level LEVEL --title "title" --topic "topic"`. Author the selected modules and remove scaffold instructions. Save the item's `decision_contract` as scratch JSON to validate with `python scripts/validate_note.py "draft.md" --contract "contract.json"`. For required implementations, run `python scripts/plan_notes.py verify-runtimes "vault" PLAN ITEM "draft.md"` and record verbatim execution evidence under [authoring rules](shared/authoring_rules.md#evidence).
6. Complete semantic QA and source receipts under the [coverage protocol](references/source-fidelity.md). Publish with `python scripts/plan_notes.py publish "vault" PLAN ITEM "draft.md"`; add `--coverage "coverage.json"` for an inventoried deep plan. Publish verifies required runnable examples in trusted drafts. Pass `--export-code` to save verified examples under `assets/<topic>/examples/`. Keep the draft until success and continue pending items. Finish with `python scripts/verify_vault_notes.py "vault" --files FILES`, `python scripts/vault_graph.py "vault" --topic "topic" --check-cycles`, and the [semantic verification checklist](references/verification_checklist.md).

Planner output includes the authoritative saved plan and per-item status. It does not research or write prose. New topic plans append a practice set; manual practice does not append another. Custom layouts use the manifest workflow rather than built-in heading enforcement.

# Scriptorium routing

## Intent

Parse with `python scripts/plan_notes.py inspect "request"` or `python scripts/scribe.py route "request"`. Explicit `/scribe-*` command locks outrank explicit template/artifact selectors; selectors outrank dominant-intent classification and standalone-source defaults. Negated artifact requests (`"don't make a cheat sheet"`) are stripped before classification. Source-policy constraints (`strict` / `source_first`) are never overridden by template routing. See [routing-policy.md](references/routing/routing-policy.md) and [master-registry.yaml](references/routing/master-registry.yaml).

### Seven Canonical Master Output Templates (`M1–M7`)

| Master | Route | Purpose | Template |
|---|---|---|---|
| **M1** | `deep-notes` (`deepstudy-master`) | Comprehensive first-principles deep learning notes | [deep-notes.md](references/templates/masters/deep-notes.md) |
| **M2** | `study-notes` (`studynotes`) | Source-aligned or syllabus-aligned structured study notes (`lecture_order` variant) | [study-notes.md](references/templates/masters/study-notes.md) |
| **M3** | `quick-reference` (`cheat-sheet`) | High-density cheat sheets, formula sheets, syntax/command references, atomic cards | [quick-reference.md](references/templates/masters/quick-reference.md) |
| **M4** | `worked-solutions` | Problem-centered step-by-step worked solutions with method selection & verification | [worked-solutions.md](references/templates/masters/worked-solutions.md) |
| **M5** | `implementation-guide` (`dsa`) | Build, implement, trace, test, and debug technical solutions with verified code | [implementation-guide.md](references/templates/masters/implementation-guide.md) |
| **M6** | `assessment` (`practice`) | Active recall practice sets, flashcards, mock exams, and diagnostic self-testing | [assessment.md](references/templates/masters/assessment.md) |
| **M7** | `synthesis-revision` | Comparisons, paper breakdowns, source summaries, concept maps, exam revision packs | [synthesis-revision.md](references/templates/masters/synthesis-revision.md) |

### Active Public `/scribe-*` Commands

| Command | Role / Routing | Load next |
|---|---|---|
| `/scribe-notes` | **Universal Adaptive Note Creation (`M1`–`M7`)** — Interactive configuration gate (`scripts/scribe.py notes start`), scope detection (`S0`–`S5`), single-note vs. hierarchical multi-note collection planning, EIS-01..EIS-07 + ARRIE + Obsidian Properties generation, and collection-wide validation | [Pre-generation gate](references/workflows/notes-creation/pre-gen-gate.md) + [Adaptive engine](references/workflows/notes-creation/adaptive-engine.md) + [ARRIE research engine](references/workflows/research/research-engine.md) + selected master (`M1`–`M7`) |
| `/scribe-doubt` | Read existing notes only; no edits or external research | [Command A](references/workflows/notes-creation/command-playbooks.md#command-a) only |
| `/scribe-quiz` | **M6 (`mock_exam`)** — One question at a time from existing notes; log weak spots in body | [Command G](references/workflows/notes-creation/command-playbooks.md#command-g) only |
| `/scribe-setfolder` | Configure default target Obsidian notes folder in `~/.scriptorium-config.json` | Vault config only |

> **Retired public note-creation wrappers:** `/scribe-deepnotes`, `/scribe-distill`, `/scribe-atomic-notes`, `/scribe-compare`, `/scribe-dsa`, `/scribe-practice`, `/scribe-ingest`, and `/scribe-expand` have been unified into `/scribe-notes`. Their internal playbooks (`B`, `C`, `D`, `E`, `F`, `H`, `I`) and master templates (`M1`–`M7`) remain fully active inside `/scribe-notes`, and invoking any retired command emits a graceful migration hint to `/scribe-notes`.

Routing selects the output product (`M1–M7` + optional variant) strictly by user intent and deliverable format, independent of subject domain. Knowledge-type subtemplates ([references/templates/subtemplates/](references/templates/subtemplates/README.md)) and instructional planning ([adaptive-engine.md](references/workflows/notes-creation/adaptive-engine.md)) operate orthogonally inside the selected master. [Command playbooks](references/workflows/notes-creation/command-playbooks.md) own command-specific operations. A broad learning request without an explicit format defaults to **M1** ([deep-notes.md](references/templates/masters/deep-notes.md)). If missing source material prevents faithful coverage, request the missing source; independent explanation may proceed only with its origin labeled.

## Plan and publish

1. Resolve vault: explicit path, `SCRIPTORIUM_VAULT_PATH`, then local configuration. Use `python scripts/vault_index.py "vault" --discover --topic "topic"`. Preserve existing placement, IDs, tags and filenames; see [pre-generation gate](references/workflows/notes-creation/pre-gen-gate.md).
2. Build a dependency-ordered outline with `title` and `routing_reason`. For deep study (`M1`), author the structured per-concept `instructional_plan` from the [adaptive engine](references/workflows/notes-creation/adaptive-engine.md) (audience, source policy/inventory, concepts, knowledge types, objectives, prerequisites, and independent concept depths `0–5`). Legacy outline fields (`purpose`, `impl_weight`, `density`, `math_level`) remain isolated in `scriptorium/engines/_instructional.py` for historical compatibility and must not replace a structured `instructional_plan` on new deep notes. Set `implementation_stack` per note or pass `--stack` for explicit user choices.
3. Persist with `python scripts/plan_notes.py start "vault" --request "request" --topic-folder "folder" --outline "outline.json"`. Resume saved plans rather than recreating outputs. Use the [syllabus contract](references/workflows/notes-creation/syllabus-template.md) for a multi-note curriculum; a single note needs no syllabus.
4. Load the selected master/variant template, [authoring rules](shared/authoring_rules.md), [math gates](shared/math_gates.md), and only the selected entries from [instructional-registry.json](references/workflows/notes-creation/instructional-registry.json). The saved `decision_contract` (`contract_version: 3`) owns the normalized `instructional_plan`, composed concept sequences, dependency graph, code depth, and stack. New deep contracts have no subject math ceiling. Run concept-specific research planning, source discovery, claim verification, and compact evidence packaging via the [ARRIE research engine](references/workflows/research/research-engine.md) (`scriptorium/engines/research.py (`scripts/scribe.py research`)`) and [resource recommendations](references/workflows/research/resource-recommendations.md) (keeping further-learning curation strictly separate from factual citations).
5. Scaffold into scratch with `python scripts/scaffold_note.py --template ROUTE --math-level LEVEL --title "title" --topic "topic"`. Author the selected modules from the compact `research_package` and `pedagogical_plan` (`scriptorium/engines/pedagogy.py (`scripts/scribe.py pedagogy`)`) and remove scaffold instructions. Save the item's `decision_contract` as scratch JSON to validate with `python scripts/validate_note.py "draft.md" --contract "contract.json"` (add `--evidence "evidence.json"` for citation auditing and `--pedagogical-plan "ped.json"` for P07 educational quality checks). For required implementations, run `python scripts/plan_notes.py verify-runtimes "vault" PLAN ITEM "draft.md"` and record verbatim execution evidence under [authoring rules](shared/authoring_rules.md#evidence).
6. Complete semantic QA and source receipts under the [coverage protocol](references/workflows/research/source-fidelity.md). Publish with `python scripts/plan_notes.py publish "vault" PLAN ITEM "draft.md"`; add `--coverage "coverage.json"` for an inventoried deep plan and `--evidence "evidence.json"` to persist and verify the ARRIE evidence registry. Publish verifies required runnable examples in trusted drafts. Pass `--export-code` to save verified examples under `assets/<topic>/examples/`. Keep the draft until success and continue pending items. Finish with `python scripts/verify_vault_notes.py "vault" --files FILES`, `python scripts/vault_graph.py "vault" --topic "topic" --check-cycles`, and the [semantic verification checklist](references/workflows/validation/verification-checklist.md).

Planner output includes the authoritative saved plan and per-item status. It does not research or write prose. New topic plans append a practice set; manual practice does not append another. Custom layouts use the manifest workflow rather than built-in heading enforcement.
